## 四个原创工具（上游没有）

### `vw-segment.mjs` —— 长视频分段并行量测

```bash
node vw-segment.mjs <视频> [--segments N | --seg-seconds S] [--parallel P] [--plan]
                                 [--accurate] [--keep] [--vw /path/to/vw.py]
```

脚本会先找**与自己同目录**的 `vw.py`；不在同目录时用 `--vw` 或环境变量 `VW_PY` 指定（找不到会明确报错并给出三种指定方式）。

probe 是唯一的线性成本（≈0.5×时长）。本工具按**关键帧**切段（坑#8：逐个 `-ss -c copy` 会让段间重叠、时间戳漂移）、并行跑各段 probe、再按实测偏移合并成一份可直接喂 `plan`/`sheet` 的 timeline。
实测 12 分钟素材分 4 段：合并后帧数与原始一致（默认模式；--accurate 会因重编码而略有出入），时长偏差约 0.2~0.8%（= 1/(fps×段长)，段越短、帧率越低偏差越大）。

### `bgm-id.py` —— 背景音乐识别（四级兜底）

```bash
python3 bgm-id.py <视频或音频> [更多文件...] [--no-fallback]
```

| 级 | 手段 | 实测边界 |
|---|---|---|
| 1 | 整段 Shazam | 能扛住「BGM 比人声低 15dB」；**只要音频里有停顿，-25dB 也能认** |
| 2 | 声道相减（立体声） | 成本为零，老式混音有效 |
| 3 | VAD 找语音空隙逐段识别 | **连续不停顿的口播没有空隙可钻**（实测 25 秒无间断 = 0 段空隙）|
| 4 | demucs 人声分离 | 适用窗口仅 -18~-20dB；更低的会**误匹配**（坑#18），CPU 推理约 8~10 倍实时 |

AcoustID 作为元数据补充（需 key，见 `~/.dsh/acoustid-key.txt`）；但它**几乎不抗人声**（坑#12）。

### `audio-match.py` —— 同源判定 + 变速变调参数反推

```bash
python3 audio-match.py <待判定音频> <参考音频> --baseline <无关素材> [--baseline <更多基线>]
```

基线用 `--baseline` 显式指定（也可把文件名写成含 `unrelated`/`baseline`/`无关` 的形式）。
**不指定基线时工具会明确警告并说明结果不可用于下结论**——因为未经校正的裸相似度对判定同源没有意义。

指纹识别答不了"这段 BGM 是不是从某首歌改的"（处理过就匹配不上）。本工具做和声层面的判定。
**三个必须知道的点**：裸相似度没有语义；把 query 音高移位后相似度**反而更高**；判据是**自洽性**——单一"改播放速率"操作下 `半音数 ≈ 12×log2(速度比)`。
实测案例：Love Hurt beat ← 病名为爱，峰值落在 (+1 半音, ×0.94)，而 `12×log2(0.94) = −1.07` 与之吻合 → 同源，**放慢约 6% + 降调 1 个半音 + 去人声**（方向经 Shazam 裁决：把待判定升 1 半音并加速 6.4% 后能被识别为原曲）。


### `audio-match.py` 的实测边界（重要，别高估它）

**它只能判「这段音频是不是那段音频本身被整体变速/变调处理过」，不能判「两段录音是不是同一首歌」。**

实测（同一组 60 秒素材，绝对相似度，基线均 ≈0.59）：

| 场景 | 绝对相似度 | 能不能判 |
|---|---|---|
| **同一录音**变速 0.94× | **0.9567** | ✅ 清晰可判 |
| 同一首歌 · 现场版 | 0.8000 | ⚠️ |
| 同一首歌 · 女声翻唱 | 0.7271 | ⚠️ |
| 无关曲目 A | 0.6390 | ⚠️ |
| 无关曲目 B | **0.7399** | ❌ 比同源翻唱还高 |

「同歌不同录音」与「无关曲目」的分数**区间重叠**，因此无法判别。

**基线校正的"增益"更不能当判据**：同一条无关对换三种基线，增益分别是
+0.0466 / +0.1678 / +0.7530（差 15 倍），而且三种基线下**无关对的增益都高于同源对**
——它主要反映基线素材本身。

根因：没有按节拍对齐（beat-synchronous chroma）、没有 DTW。
标准做法属于 cover song identification（Covers80 / SHS100K 那类任务）。
我试做过一个 beat-sync + DTW 的最小原型，判别力同样不足
（最无关的一对反而得 0.82，高于同录音变速的 0.62），且归一化实现本身有疑点
—— 要真正解决需要完整实现 + 在真实数据集上评测，不是能顺手补上的东西。
